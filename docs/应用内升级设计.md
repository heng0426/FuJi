# 应用内升级设计与发布手册

> 适用版本：1.4.0 起
> 相关代码：`app/src/main/java/com/xiaofu/daily/update/`、`app/src/main/java/com/xiaofu/daily/ui/update/`

## 1. 分发形态

个人与亲属自用，不上架应用商店，走 GitHub Releases（仓库公开）：

```
https://github.com/heng0426/FuJi/releases/latest/download/update.json
https://github.com/heng0426/FuJi/releases/latest/download/xiaofu.apk
```

两个资源名固定，`latest` 永远指向最新正式版，因此 App 内的地址是常量，不需要
`api.github.com`（避免每小时 60 次的匿名限流）。版本信息全部由 `update.json` 描述。

## 2. 版本清单契约

```json
{
  "versionCode": 14,
  "versionName": "1.4.0",
  "apkUrl": "https://github.com/heng0426/FuJi/releases/latest/download/xiaofu.apk",
  "sha256": "64 位十六进制",
  "sizeBytes": 20906820,
  "minSdk": 28,
  "changelog": ["新增…", "修复…"],
  "mirrors": [],
  "publishedAt": "2026-11-27"
}
```

- 字段只增不减，客户端忽略未知字段；新增字段必须有默认值。
- `apkUrl` 必须 HTTPS；`mirrors` 为 APK 备源，按顺序重试。
- 清单本身的备源在 `UpdateConfig.MANIFEST_MIRRORS`，当前为空。

## 3. 客户端链路

0. **双通道取清单**：先试 `releases/latest/download/update.json`（快、不耗 API 配额）；
   失败后回落 `api.github.com/repos/<repo>/releases/latest`，按资产名找 `update.json`
   与 `xiaofu.apk`。实测部分网络只屏蔽 `github.com`，而 `api.github.com` 与
   `objects.githubusercontent.com` 可达，这条回落是该环境下的主用路径。
   清单若来自 API，APK 下载也优先使用 API 资产地址，避免再次等待必然失败的超时。
1. **检查**：`UpdateChecker` 拉清单 → `UpdateRepository.check()` 比较 `versionCode` 与 `minSdk`。
2. **下载**：`ApkDownloader` 写 `cacheDir/update/`，先写 `.part` 再改名；空间不足直接拒绝。
3. **校验**：`ApkVerifier` 四项全过才继续——文件大小、SHA-256、包名、签名证书摘要。
4. **授权**：`PackageManager.canRequestPackageInstalls()` 为 false 时，引导到
   `ACTION_MANAGE_UNKNOWN_APP_SOURCES`。
5. **安装**：`PackageInstaller` 全量安装会话，`setRequireUserAction(USER_ACTION_REQUIRED)`
   保留系统确认页；结果由 `InstallResultReceiver` 接收。
6. **交接**：成功/失败写入 `UpdateStore`（SharedPreferences），下次启动提示一次；
   失败同时发通知，避免进程被杀后无感知。

状态机集中在 `UpdateManager`（object + StateFlow），界面只消费状态：
`Idle → Checking → Available → Working → NeedsPermission / Failed`。

## 4. 为什么不做静默安装

Android 12+ 声明 `UPDATE_PACKAGES_WITHOUT_USER_ACTION` 并对自更新调用
`setRequireUserAction(USER_ACTION_NOT_REQUIRED)` 可以免确认，但：

- 依赖各厂商 ROM 是否遵守，实际成功率不可控；
- 会扩大权限面，个人自用没有必要；
- 保留系统确认页可让用户看清安装来源。

因此当前固定为「用户确认式」。

## 5. 发布流程

```bash
# 1. 改版本与更新说明（唯一来源）
#    version.properties: versionCode / versionName / changelog

# 2. 出包（自动生成 dist/xiaofu.apk、版本化 APK、update.json）
./gradlew :app:releaseArtifacts

# 3. 提交并打 tag
git add -A && git commit -m "release: 小福日常 1.4.0"
git tag v1.4.0
git push origin feature/in-app-update v1.4.0

# 4. 发布（两个资源必须同时上传，latest 才能取到清单）
gh release create v1.4.0 dist/xiaofu.apk dist/update.json \
  --title "小福日常 1.4.0" --notes-file docs/发布说明-1.4.0.md
```

发布后自检：

```bash
curl -L https://github.com/heng0426/FuJi/releases/latest/download/update.json
```

## 6. 版本兼容与回滚

| 场景 | 结果 |
|---|---|
| 同数据库版本升级 | 覆盖安装，数据保留，可回滚（装回旧版） |
| 跨数据库版本升级 | 可升级；回滚需卸载 → 装旧版 → 导入升级前备份 |
| versionCode 回退 | 系统拒绝（`INSTALL_FAILED_VERSION_DOWNGRADE`） |
| 签名不一致 | 系统拒绝（`INSTALL_FAILED_UPDATE_INCOMPATIBLE`） |

约束：数据库迁移只增不删；破坏性变更拆两版发布；`versionCode` 永不复用；
历史 APK 永久保留在 GitHub Release 中。

升级前自动备份写到「下载/小福日常」，由**旧版本**生成，因此 schema 不高于旧版，
回滚后旧版本可以直接导入。升级后新增的数据会丢失，这是单向迁移的固有代价。

## 7. 签名

- 证书：`D:/Develop/Android/keys/xiaofu-release.jks`（不入库），别名 `xiaofu`。
- 口令：`keystore.properties`（已 gitignore）。
- 必须离线双备份：`.jks` 文件 + 口令 + 证书 SHA-256 指纹。
- **私钥丢失等于永久失去升级能力**，届时只能换包名重新分发。

## 8. 后续可扩展

- 国内备源：在 `update.json` 的 `mirrors` 填入对象存储地址，客户端无需改动。
- 灰度：清单增加 `minVersionCode` 或设备白名单，客户端按需读取。
- 强制更新：增加 `minSupportedVersionCode`，低于该值只保留「立即更新」。
