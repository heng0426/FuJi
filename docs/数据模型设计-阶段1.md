# 小福日常 · 数据模型设计（v1.2 · 已实现）

> 状态：**已实现，DB version 1 已冻结（2026-11-22）**；本文档于 2026-11-23 按 7 轮迭代补充设置键与约束
> 冻结含义：字段/枚举/表名变更需走版本迁移；设置键与预填值的新增不涉及表结构
> 存储：Room 2.8.5 + SQLite，全部落在应用私有目录 `/data/data/com.xiaofu.daily/databases/xiaofu.db`

---

## 0. 通用约定

| 项 | 规则 |
|----|------|
| 主键 | `id: Long` 自增；单宠场景下 `profile.id` 固定为 1 |
| 时间戳 | 事件发生时刻用 `Long`（epoch 毫秒）；纯日期（生日/到期日）用 `Long`（epochDay，1970-01-01 起的天数），避免时区漂移 |
| 枚举 | Kotlin enum + Room TypeConverter，DB 存英文常量名（TEXT）。**上线后枚举常量名不可改名**（改名 = 数据迁移） |
| 单表多态 | 六类记录共用 `records` 表，类型专属列可空；"哪类记录必填哪些字段"由仓储层校验（见 §5） |
| 文本长度 | 备注 ≤500 字、名称类 ≤50 字，UI 层限制（DB 不设 CHECK 约束，避免迁移复杂化） |
| 命名 | 表/列 = 小写下划线；Kotlin 属性 = 驼峰，Room 自动映射 |
| 文件路径 | 照片只存**文件名**（如 `r12_1.jpg`），不存绝对路径——换机恢复/路径变更不失效 |

## 1. 表结构

### 1.1 records —— 核心记录表（单表多态）

| 列 | 类型 | 空 | 说明 |
|----|------|----|------|
| `id` | INTEGER PK | 否 | 自增 |
| `pet_id` | INTEGER | 否 | 默认 1，预留多宠 |
| `type` | TEXT | 否 | `RecordType` 枚举 |
| `occurred_at` | INTEGER | 否 | 发生时刻（epoch ms），可修改（补录） |
| `note` | TEXT | 是 | 通用备注，所有类型可用 |
| `created_at` | INTEGER | 否 | 创建时刻 |
| `updated_at` | INTEGER | 否 | 最后修改时刻 |
| `amount_ml` | INTEGER | 是 | 喝水：毫升 |
| `meal_kind` | TEXT | 是 | 喂食：`MealKind`（MAIN/SNACK） |
| `serving_count` | REAL | 是 | 喂食：份数。**新记录为 1–20 整数**；历史数据可能存在 0.5 等半份值，按原值展示 |
| `grams_per_serving` | INTEGER | 是 | 喂食：每份克重 |
| `total_grams` | INTEGER | 是 | 喂食：本次总克数（**冗余存库**，设置变更不改写历史） |
| `snack_type` | TEXT | 是 | 加餐类型（冻干/罐头/零食/自制/其他） |
| `weight_grams` | INTEGER | 是 | 体重：**克**（UI 以"斤"展示，0.1 斤 = 50 g 步进） |
| `deworm_kind` | TEXT | 是 | 驱虫：`DewormKind`（INTERNAL/EXTERNAL） |
| `medicine` | TEXT | 是 | 驱虫：药品名 |
| `next_due_date` | INTEGER | 是 | 驱虫/疫苗：下次到期（epochDay），可手动覆盖 |
| `vaccine_name` | TEXT | 是 | 疫苗名称 |
| `anomaly_category` | TEXT | 是 | 异常：分类标签名（文字快照，不引用标签表） |
| `severity` | TEXT | 是 | 异常：`Severity`（LIGHT/MEDIUM/HEAVY） |

## 4. DAO 方法清单

### RecordDao

| 方法 | 签名要点 | 用途 |
|------|----------|------|
| `insert` / `update` / `deleteById` | suspend | 增改删（详情页） |
| `getById` | suspend → `RecordEntity?` | 详情加载 |
| `observeDay` | `(startMs, endMs)` → `Flow<List>` | 首页当日时间线、日历选日 |
| `observeTimeline` | `(beforeMs, limit)` → `Flow<List>` | **keyset 分页**（`occurred_at < :before`），每页 100 条，UI 累积 |
| `observeByType` | `(type, limit)` → `Flow<List>` | 记录页筛选列表 |
| `observeByRange` | `(startMs, endMs)` → `Flow<List>` | **月历标记**：取当月记录后在 Kotlin 按本地日期分组，规避 SQL 时区问题 |
| `observeLatestWeight` | `Flow<RecordEntity?>` | 首页"最近体重" |
| `observeWeights` | `Flow<List>` | 体重趋势折线图 |
| `getLastWaterAmount` | suspend → `Int?` | 喝水弹窗预填（优先 settings，回落最近一条） |
| `observeDayWaterMl` | `(startMs, endMs)` → `Flow<Int?>` | 概览卡今日喝水合计（SUM） |
| `observeDayFoodSummary` | `(startMs, endMs)` → `Flow<List<FoodDaySummary>>` | 概览卡"主粮 x份x克 · 加餐 x份x克"（GROUP BY meal_kind 的 SUM） |
| `observeLatestDeworm` | `(kind)` → `Flow<RecordEntity?>` | 内/外驱下次到期与倒计时 |
| `observeLatestVaccine` | `Flow<RecordEntity?>` | 最近一条含 next_due_date 的疫苗 |
| `getUpcomingDue` | `(fromDay, toDay)` → `List` | 提醒 Worker 扫描 T-3/T-0 |

聚合 POJO：`FoodDaySummary(mealKind, servings: Double, grams: Int)`。

## 5. 按类型的字段有效性约束（仓储层校验，非 DB 约束）

| 类型 | 必填 | 选填 | 校验规则 |
|------|------|------|----------|
| WATER | `amount_ml` | `note` | 5–500 ml 软校验（超出提示但可保存） |
| FOOD | `meal_kind`、`serving_count`、`grams_per_serving`、`total_grams` | `note`、`snack_type`（仅 SNACK） | **新记录份数 1–20 整数**；每份 1–200 g；`total_grams = round(份数 × 克重)`；历史 0.5 份按原值统计 |
| WEIGHT | `weight_grams` | `note` | 0.1–50 斤（50–25000 g），0.1 斤步进，展示保留 1 位小数 |
| DEWORM | `deworm_kind` | `note`、`medicine`、`next_due_date` | `next_due_date` 默认 = 记录日期 + 周期，可手改 |
| VACCINE | `vaccine_name` | `note`、`next_due_date` | 填写 `next_due_date` 才参与提醒 |
| ANOMALY | `anomaly_category` | `note`、`severity`、照片 | 照片 ≤3 张（长边 2560 px / JPEG 90%），压入私有目录 |

## 6. 删除与级联策略

1. **删除记录**：FK 级联删除 `record_photos` 行；照片文件由"孤儿文件清理"异步删除（App 启动时比对 DB 引用）。
2. **删除自定义标签**：不影响历史记录——`anomaly_category` 存的是文字快照。
3. **替换档案头像**：新图落盘成功后删旧文件。
4. **单条删除撤销**：删除时取 `RecordSnapshot`（记录 + 照片行），Snackbar 5 秒内可回写；批量删除不生成快照，UI 二次确认后直接删。
5. **不提供"清空全部数据"**（v1），待 v1.1 导出备份就绪后再评估。

## 7. 版本与迁移

- DB `version = 1`，`exportSchema = true`，`schemas/` 目录纳入版本库（供迁移测试）。
- v1.1 以来的功能（份数记忆、预设、类型顺序、主题）**仅新增 settings 行/SharedPreferences，不涉及表结构变更**，因此 version 仍为 1。
- 外观偏好存 `SharedPreferences("xiaofu_prefs").theme_mode`（SYSTEM/LIGHT/DARK），在 `setContent` 前读取以避免启动闪烁；不属于 Room 设置表。
- **禁用 destructive migration**：健康记录不可丢。
- 后续任何表结构变更：version+1 + 手写 `Migration` + 迁移测试，不允许"重装解决"。

## 10. 确认结论（2026-11-22 定稿）

| # | 项 | 结论 | 来源 |
|---|----|------|------|
| 1 | 体重单位与精度 | **按"斤"计量，0.1 斤步进**；DB 以克（INTEGER）存储，展示时 ÷500 保留 1 位小数 | 用户指定 |
| 2 | 照片规格 | **长边 2560 px、JPEG 90%**，单条最多 3 张 | 用户指定（提高画质） |
| 3 | 喝水单次范围 | 5–500 ml 软校验（超出提示，不阻断保存） | 推荐采纳 |
| 4 | 每份克重范围 | 1–200 g；份数 1–20 整数（历史半份保留） | 实现调整 |
| 5 | 生日精度 | 完整日期（选填），不支持"只知年月" | 推荐采纳 |
| 6 | 提醒时刻 | 默认 09:00，设置页可改小时（WorkManager 每小时检查） | 实现调整 |
| 7 | 异常预设分类 | 8 类预设 + 自定义 | 推荐采纳 |
| 8 | 清空全部数据 | v1 不做 | 推荐采纳 |

> 字段冻结结论：原草案 `weight_kg`（REAL）改为 `weight_grams`（INTEGER，克）；其余字段与本文档 §1–§9 一致。冻结后变更需走版本迁移。

## 11. 实现补充（2026-11-23）

| 项 | 实现 |
|----|------|
| 删除快照 | `RecordSnapshot(record, photos)`；恢复时重新插入记录与照片行，照片文件不删 |
| 设置读取 | 未写入的键使用代码默认值，不强制首启写入；`last_servings` / `last_weight_grams` 支持回退最近记录 |
| 喂食预设 | 仅自定义预设持久化为 JSON；内置早餐/晚饭由 `FoodPreset.defaults` 提供，不参与删除 |
| 类型顺序 | 逗号分隔枚举名；读取时补齐缺失类型、去重，保证六类完整 |
| 提醒 | `DueReminderWorker` 每小时检查，`notify_hour` 到点后当天一次；`notify_last_day` 去重 |
| 主题 | Room 之外独立存储；`LocalAppDarkTheme` 供业务 UI 取色，避免强制深色误用系统值 |
